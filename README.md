# Literature Keyword Co-occurrence Network

**English** | [简体中文](README.zh-CN.md)

Extract, guide, and audit keywords from collections of English-language PDF papers, then build publication-level co-occurrence networks as CSV, GraphML, PNG, and interactive HTML outputs.

> [!IMPORTANT]
> This project, including its source code and documentation, was generated by AI under human direction. It may contain errors or unsuitable assumptions. Review the code and validate all outputs before using them for research, publication, or decision-making.

## Features

- Three workflows: unguided extraction, user-guided discovery, and exact keyword matching.
- Comma-separated UTF-8 keyword files with support for multi-word terms.
- TF-IDF ranking of one- to three-word candidate phrases.
- Conservative semantic merging with auditable merge suggestions.
- Colored semantic groups for related nodes in both PNG and interactive HTML networks.
- Interactive edge-width normalization to reduce the visual dominance of frequently occurring terms.
- Paper-by-keyword and keyword-by-keyword matrices for downstream analysis.

## Requirements

- Python 3.10 or later
- PDFs containing extractable text

> [!NOTE]
> Scanned PDFs must be processed with OCR before they can be analyzed.

## Installation

Install the required Python packages:

```bash
python -m pip install pymupdf scikit-learn sentence-transformers networkx matplotlib pandas numpy
```

The first semantic-analysis run downloads the `all-MiniLM-L6-v2` model. Subsequent runs use the local cache.

## Quick start

Place at least two PDF files in a directory, for example `papers/`, and run:

```bash
python literature_keyword_network.py ./papers
```

Results are written to `keyword_network_results/` by default.

## Use custom keywords

Create a UTF-8 text file containing comma-separated keywords. Terms may contain spaces:

```text
climate change, renewable energy, carbon emissions, biodiversity
```

The included [`keywords.example.txt`](keywords.example.txt) shows the expected format.

### Guided discovery

Guided mode is the default when a keyword file is provided:

```bash
python literature_keyword_network.py ./papers --keywords-file keywords.txt
```

The supplied terms define the topic rather than limiting the output. They are used to:

- locate relevant sentences and their surrounding context;
- derive topic anchors and filter unrelated candidates;
- prioritize supplied terms and related phrases; and
- prevent distinct user-specified concepts from being merged automatically.

Adjust the number of surrounding sentences with `--context-window`:

```bash
python literature_keyword_network.py ./papers \
  --keywords-file keywords.txt \
  --context-window 2
```

### Exact matching

Use exact mode to measure only the supplied terms:

```bash
python literature_keyword_network.py ./papers \
  --keywords-file keywords.txt \
  --keyword-mode exact
```

Matching is case-insensitive and respects word boundaries. Empty entries are ignored, whitespace is normalized, and duplicate terms are removed in first-seen order. Terms that do not occur remain in the CSV outputs with a frequency of zero.

`--custom-keywords` is an alias for `--keywords-file`.

## Semantic grouping

After highly similar candidates are merged, related nodes that remain separate are assigned to semantic groups. Members of each group share a colored outline and are enclosed by a translucent rounded box in the PNG and HTML networks.

The default grouping threshold is `0.72`. Higher values create stricter groups:

```bash
python literature_keyword_network.py ./papers \
  --keywords-file keywords.txt \
  --group-threshold 0.78
```

Set `--group-threshold 0` to disable grouping. To retain nearly all original nodes and represent synonymy mainly through grouping, raise the merge threshold:

```bash
python literature_keyword_network.py ./papers \
  --keywords-file keywords.txt \
  --merge-threshold 1.0 \
  --group-threshold 0.72
```

Group membership is also written to `semantic_groups.csv` and the `semantic_group` GraphML node attribute.

## Edge-width normalization

Open `keyword_network.html` and use **Normalize edge width** in the toolbar:

- Off: width represents the number of papers in which both keywords occur.
- On: width represents the normalized association
  `cooccurrence / sqrt(frequency1 × frequency2)`.

Normalization reduces the visual advantage of terms that are frequent because the paper collection is topic-biased. It changes only edge appearance, not the network structure or exported data. The **Association** slider independently filters weak connections.

## Network interpretation

- **Node size:** number of papers containing the keyword.
- **Edge width:** raw co-occurrence count by default; normalized association when enabled in HTML.
- **Edge filter:** minimum normalized association and co-occurrence thresholds.
- **Colored enclosure:** semantically related nodes that remain distinct.

## Common options

## Troubleshooting

### Too few papers are included

- Confirm that the PDFs contain selectable text.
- Use broader guided keywords or increase `--context-window`.
- For small collections, keep `--min-df 1`.

### No edges are drawn

Lower `--min-edge` or `--min-association`, for example:

```bash
python literature_keyword_network.py ./papers \
  --keywords-file keywords.txt \
  --min-edge 1 \
  --min-association 0.2
```

CSV matrices are still generated when no edges pass the display filters.

### The semantic model cannot be loaded

Ensure `sentence-transformers` is installed and allow the first run to download the model. In an offline environment, the model must already exist in the local Hugging Face cache.
